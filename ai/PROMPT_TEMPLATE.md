# Task / handoff template

Use for a missing task card or an explicitly requested bounded delegation.
A continuation needs only the existing card and changed objective/section.
Resolve paths and decisions before dispatch; do not send placeholder inputs.

## Context

Name the scenario (or shared maintenance), checkout, owner, current run (or
none), stage and status. Record the selected notebook section and accepted
sections, or explicitly none. Read `ai/CONTEXT.md`, `ai/RULES.md`, this card and
the selected stage context.

## Objective and inputs

State one observable outcome and the endpoint of any authorized stage sequence.
List exact existing inputs and relevant sections; label future outputs as such.
For results, include the approved preview linked from `ai/RULES.md` read-only.

## Scenario claims

Use only `id`, `statement`, `basis`, `basis_type`, `validation_limit` as defined
in `ai/RULES.md`. List this scenario's expected effects and exact run references;
label unbound definitions as proposed when no run is selected. For shared
maintenance, link the owning cards instead. Do not add source-hint fields or
copy another scenario's claims. Findings are separate, human-reviewed records.

## Process and write scope

Give three to five concrete steps and exact writable paths or bounded areas.
Name immutable inputs, shared-resource ownership and authorized design limits.
Do not add guest-side postcondition checks to improve the claim reference.

## Validation and endpoint

Name focused checks, authorized transitions and the exact human checkpoint.
No automatic notebook advancement, accepted support verdicts or changed-design
experiment. Do not mark a draft done or a planned check executed.

## Last handoff

Replace, do not append. At most 12 lines: date, checkout/revision/dirty state,
artifacts, checks actually run, limitations, next action and human acceptance.
